# KSE · Публічна інформація (гілка `public-ver`)

> **Це публічна версія сайту, і вона живе тільки в гілці `public-ver`.**
> Гілка за замовчуванням, `main`, — це внутрішня версія для працівників (статуси, відповідальні, дедлайни).
> Після `git clone` ви опиняєтеся в `main`, тому спершу перемкніться на `public-ver` (див. «Запуск»).

Розділи й документи з Google Drive (`Процеси → ЄДЕБО та Ліцензування → Оновлення публічної інформації → Документи`), без типів оновлення, статусів, відповідальних і дедлайнів:

1. **Огляд** (`#/`): кожен розділ показано карткою з фото, назвою, описом і кнопкою «Детальніше».
2. **Розділ** (`#/section/<id>`): фото й опис, пошук, документи. Групи (папки з папками, як «Протидія булінгу») йдуть підзаголовками.
3. Натискання на документ відкриває його папку в Google Drive. Файли, що лежать у папці документа, показано під ним прямими посиланнями.

`#/section/all` показує всі документи; сюди веде пошук у сайдбарі (Enter або ⌘K).

## Запуск

Потрібен Node.js 20 або новіший.

```bash
git clone https://github.com/robotheist/USEDO-website.git
cd USEDO-website
git checkout public-ver
cd backend
npm install
npm start
```

Відкрийте http://127.0.0.1:3000. Якщо репозиторій уже склоновано, достатньо `git fetch && git checkout public-ver && git pull`, потім `cd backend && npm install && npm start`.

**Як переконатися, що запущено публічну версію:**
- у консолі є рядок `[public] http://127.0.0.1:3000`;
- http://127.0.0.1:3000/api/health показує `"site": "public"`;
- на сайті є «Публічна інформація КШЕ» і картки з фото, а **немає** вкладки «Дедлайни».

Якщо бачите старий сайт:
- перевірте, що ви в `public-ver` (`git branch --show-current`);
- перевірте, що запущено `npm start`, а не `npm run start:internal`;
- оновіть сторінку з очищенням кешу (Cmd+Shift+R / Ctrl+Shift+R).

Без доступу до Google сервер працює на знімку `backend/fixtures/public-drive.json`, а в консолі буде `using fixtures`.

## Живі дані з Drive

Сервер раз на хвилину перечитує папку «Документи» (`PUBLIC_REFRESH_MS`, за замовчуванням 60 000 мс). Нова папка-розділ, новий документ, група чи файл з'являються на сайті приблизно за хвилину. Сторінка сама підтягує зміни кожні 2 хвилини й коли вкладку знову відкривають.

Доступ до Google налаштовується так само, як для внутрішньої версії (`backend/README.md`, розділ «Live data»). Публічному серверу потрібне лише право **Viewer** на папку «Документи», таблиці йому не потрібні. Коли доступ є, `/api/health` показує `"source": "google"`.

## Що де лежить

| Файл | Що робить |
|---|---|
| `backend/src/public-server.js` | Публічний сервер: `npm start`. Тільки читання. Внутрішніх статусів, відповідальних і редагування тут немає (ці маршрути дають 404/405). |
| `backend/src/public/` | Читання дерева Drive (`tree.js`), джерела даних (`sources.js`), API (`app.js`) |
| `GET /api/public/tree` | Розділи → документи / групи → документи → файли. Позначки `[Регулярний]` тощо прибрано з назв. |
| `GET /api/health` | `site`, джерело даних, час оновлення, лічильники, остання помилка |
| `index.html`, `app.js`, `styles.css` | Фронтенд |
| `data.js` | Опис і фото кожного розділу (за id папки в Drive), а також знімок документів на випадок, коли сайт відкрито без бекенду. Новий розділ без запису тут отримає синій градієнт і кількість документів замість опису. |
| `backend/test/public.test.js` | Тести публічного сервера (`npm test` запускає і їх, і тести внутрішньої версії) |

Внутрішній сервер у цій гілці теж є (`npm run start:internal`), але публічний сайт ним не користується.

## Деплой

`Dockerfile` у цій гілці запускає публічний сервер. Розгортайте з гілки `public-ver` як **окремий** сервіс Cloud Run, не той, що для працівників. Цей сервіс має бути **без** входу через IAP і з `--allow-unauthenticated`, бо сайт публічний. Решта кроків така сама, як у `backend/README.md` («Deploy to Cloud Run»). `ADMIN_TOKEN` публічному серверу не потрібен.

Щоб відвідувач без облікового запису КШЕ міг відкрити документи, папки в Drive мають бути доступні всім, хто має посилання.
